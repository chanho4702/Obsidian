## 1부. 무엇을 만들었나

### 기업화 수위 — "1인 스튜디오"에서 멈춘다

가장 먼저 정한 것이 **비목표**였다.

> 가상 법인 서술("우리는", 팀·연혁·고객사)은 만들지 않는다. 1인 실체와 서술이 어긋나면 채용·영업 상황에서 **과장으로 읽힌다.**

톤은 1인칭 사실 기반을 유지하고, **기업다움은 정보구조·타이포·섹션 밀도로만** 낸다. 이 제약이 이후 모든 결정의 상한선이 됐다 — 콘텐츠는 "실제 리포에서 사실 추출", **확인하지 못한 사실은 쓰지 않고 그 행 자체를 렌더하지 않는다**(빈 값 표시 금지).

### 정보구조

```
/                   홈 — 게이트웨이형 랜딩. 요약과 유입만
/products           제품 인덱스 (오픈소스 4 + 사내 2)
/products/:slug     제품 상세 — 스펙 테이블 · 아키텍처 · 링크
/tech               기술 — 플랫폼 구성 · 역량 4 · 스택 · 노트 진입
/tech/notes         엔지니어링 노트 인덱스
/tech/notes/:id     노트 본문 (id = 00~19)
/about              소개 — 커리어 · 케이스스터디 · 수상
/contact            연락
```

**기존 라우트를 죽이지 않았다.** `/services/:slug` 4개는 `/tech#cap-<slug>`로 **리다이렉트**한다. `/app`·`/designs`·`/profile` 등 개발 도구 계열은 유지하되 GNB에서 빼고 **푸터 "개발 도구" 그룹으로 격리**했다 — 기업 사이트 GNB에 위키·ALM·설계문서·프로필이 섞여 있으면 산만하다.

위키(`/wiki/`)·ALM(`/alm/`)은 nginx 단일 오리진의 **별도 SPA**([[11 nginx 통합배포 + 3앱 SSO (2026-07-14)|11번]])이므로 전체 페이지 이동 링크로 두되, GNB가 아니라 `/products`의 제품 카드에서 진입시킨다.

### 시각 언어 — "엔지니어링 그리드"

| 규칙 | 내용 |
|---|---|
| Elevation | **`box-shadow` 전면 미사용.** 1px `divider` 헤어라인만으로 구분 |
| Radius | 8px → **4px** |
| 섹션 | 좌측 고정폭 모노 라벨 컬럼(`SEC.02 / PRODUCTS`) + 우측 콘텐츠, 상단 헤어라인 |
| 수치 | `tabular-nums` 강제 |
| 인터랙션 | hover = `border-color` 150ms 전이만. **`translateY` 이동 제거**(레이아웃 안정) |
| 다크모드 | 헤어라인이 `divider` 토큰이라 자동 대응. 대비는 라이트/다크 **각각 실측** |

팔레트와 서체는 **바꾸지 않았다.** 디자인 인텔리전스 스킬이 이 제품 유형에 추천한 팔레트는 현행과 사실상 동일했고, 추천 서체(Lexend / Source Sans 3)는 **한글 지원이 없어** Pretendard 유지가 옳았다. — *추천을 받되 제약(한글)으로 검증한다.*

**프리미티브 5종**(`src/site/ui/`)을 만들고 **페이지들은 이것만 조합**한다: `SectionLabel` · `GridSection` · `SpecTable` · `StatBar` · `HairlineCard`. 일관성을 리뷰가 아니라 **코드로 강제**하기 위한 경계다.

### 콘텐츠 계층 분리

케이스스터디·커리어·스택이 `Home.tsx`에 인라인 상수로 박혀 있었다. 페이지가 늘면 중복이 생긴다 → `src/site/content/`(products·capabilities·profile·stack)로 분리하고 배럴로 기존 import를 흡수했다.

## 2부. 옵시디언 노트 파이프라인

### 왜 빌드타임 동기화인가

볼트의 노트를 사이트에 띄우는 방법은 여럿이다. **빌드타임 동기화(스크립트 → 번들)**를 택한 이유:

- **네트워크 의존 0** — 런타임에 볼트를 읽지 않는다
- 검색·SEO 가능 — 정적 마크다운이 번들에 들어간다
- **CI 빌드 재현성** — 볼트가 없는 러너에서도 빌드가 성공해야 한다

### `scripts/sync-notes.mjs` (Node, 무의존)

1. 소스 경로는 `OBSIDIAN_VAULT` env로 오버라이드(기본값은 로컬 볼트 경로)
2. **화이트리스트 = 파일명 `^\d\d ` 정규식**
3. frontmatter 파싱 → `index.json`(번호·제목·태그·작성일·상태)
4. 본문 변환 — `[[대상]]`이 **화이트리스트 안**이면 `/tech/notes/<번호>` 링크, 밖이면 일반 텍스트로 평탄화(끊긴 링크 0). `> [!note]` 콜아웃은 MUI `Alert` 마커로 정규화
5. 산출물 `src/site/content/notes/*.md` + `index.json`을 **git에 커밋**
6. 볼트 경로가 없으면 **경고만 출력하고 성공 종료** — 기존 산출물 유지
7. 검증 리포트: 화이트리스트 밖 파일 유입 / 깨진 위키링크 / frontmatter 누락

> [!important] 2번이 이 파이프라인의 핵심이다
> `auth-server 면접 방어 시트`처럼 **같은 폴더에 있는 개인 준비물**이 사이트에 올라가면 안 된다. 방법은 두 가지 — 게시 목록을 손으로 관리하거나, **구조로 배제**하거나.
>
> 손으로 관리하면 언젠가 빠뜨린다. 파일명 규칙(번호 시리즈)을 화이트리스트로 삼으면 **새 파일은 기본이 비공개**이고, 공개하려면 번호를 붙여 시리즈에 편입해야 한다. 실수의 방향이 안전한 쪽이다.

**렌더**는 `react-markdown` + `remark-gfm` 2개만 쓴다. 코드 하이라이터는 **의도적으로 제외**(번들 절약, 필요해지면 나중에). 노트 본문에는 목차 + 이전/다음 이동을 붙였다.

### 실측이 설계를 바꾼 지점 세 곳

**① 제목 번호 중복 / status 오염** — 노트 20편 중 11편의 제목에 번호가 이미 들어 있었고, frontmatter `상태` 값은 3~237자에 SHA·굵게·위키링크가 섞여 있었다. → `stripNumberPrefix` / `statusLabel` 도입(계획 개정).

**② `useMemo` 캐시 클로저가 목차를 전멸시킬 뻔했다** — 헤딩 id 생성기의 중복 카운터(`seen`)가 **리렌더 사이에 생존**해서, 다크모드 토글 한 번에 모든 헤딩 id에 `-1`이 붙었다. 목차 앵커가 전부 깨진다. → 실측(헤딩 196개, 노트 내 중복 0)에 근거해 **카운터를 제거하고 id를 순수 `slugify(text)`로 고정**.

**③ `getElementById`여야 했다** — 해시 스크롤 구현에서 `querySelector('#'+id)`가 아니라 `getElementById(id)`를 쓰기로 한 결정이, 노트 배선 단계에서 값을 했다. **헤딩 196개 중 56개가 숫자로 시작**한다. `querySelector`였다면 `#1단계`에서 CSS 파싱 `SyntaxError`가 나서 **목차의 1/4 이상이 무음 파손**됐을 것이다.

> [!tip] 세 건의 공통점
> 전부 **"현재 데이터를 세어보고" 결정**했다. 추상적으로 "중복이 있을 수 있으니 카운터를 두자"가 아니라, 196개를 실제로 세어서 중복 0을 확인하고 카운터를 없앴다. 방어 코드가 오히려 버그였던 경우다.

## 3부. 리뷰가 잡은 것 — 하네스의 값

[[21 dev-offset 개발환경 클러스터 + 6롤 에이전트 하네스 (2026-07-22)|6롤 하네스]]로 돌린 첫 대형 작업이었다. 리뷰 롤이 잡은 것 중 **다른 방법으로는 못 잡았을** 것들.

### ① 게시 전에 걸린 사실오류 (Critical)

계획서에 이렇게 쓰여 있었다:

> 스틸 블루 `#1B66C9` — 세 프론트의 색이 어긋나지 않는다

리뷰가 **실측**했다:

| 대상 | 실제 |
|---|---|
| design-system tokens **0.3.0** | `#0C66E4` |
| wiki-front | 0.3.0 소비 |
| alm-front | **0.2.0 소비**(정체) |
| myFront 테마 | `#1B66C9` |

즉 **세 프론트의 색이 실제로 어긋나 있었다.** 그대로 게시하면 누구나 확인 가능한 거짓이 공개 사이트에 올라간다. → 계획·코드 둘 다 정정.

**원인**: 근거로 삼은 `CHANGELOG.md`가 0.2.0까지만 기록된 **stale 문서**였다.

> [!warning] 교훈
> **버전 있는 산출물의 사실은 CHANGELOG가 아니라 `package.json`의 version + 소스로 확인한다.** CHANGELOG는 사람이 갱신을 잊는 문서다.

부수적으로 별도 이슈 2건이 드러났다 — alm-front가 `@chanho/tokens` 0.2.0에 정체된 것, design-system CHANGELOG의 0.3.0 항목 누락. 둘 다 이 리뉴얼 범위 밖으로 분리해 보고했다.

### ② 픽셀을 재야 보이는 결함 (Important 3건)

`/about`의 아키텍처 다이어그램에서:

1. `height={200}` + `objectFit: contain` 조합이 **1549×1524 다이어그램을 203×200(원본 13%)로** 렌더 → 라벨 판독 불가. 다른 다이어그램도 20%.
2. `bgcolor: common.white` 고정이 **자체 배경이 어두운 이미지**에 역효과 — 다크모드에서 그 이미지 주위만 순백 여백.
3. `ContactPage`가 `career[0].text`를 **파라프레이즈해 인라인**했다("디무브 재직 중 —" vs 원문 "디무브 —") + 공용 URL 상수 대신 별도 리터럴 → **이직 시 조용히 낡는다.**

수정: `images`에 w/h 실측값 + `aspectRatio`로 비율 렌더, `background.paper`, "원본 크기로 보기" 링크, content 계층 참조. **재리뷰 실측**에서 레터박싱 소멸(배경 노출 ~0), 스케일 13~20% → 22~30% 확인.

1·2는 코드만 읽어서는 원리적으로 알 수 없다. 3은 **"지금 맞지만 미래에 틀어질 코드"** — 사실을 복사하지 말고 참조하라는 원칙 위반이다.

### ③ 셸에서 고칠 것을 셸에서 고쳤다 (Critical)

`/services/:slug` → `/tech#cap-<slug>` 리다이렉트가 **주소만 바꾸고 페이지 최상단에 무음 착지**했다. 원인: React Router 데이터 라우터는 **URL 해시를 스스로 처리하지 않는다**(`ScrollRestoration`/수동 처리 부재).

리뷰어는 해당 페이지 국소 수정을 제안했으나, **셸(`SitePage`)에 `useHashScroll`을 넣는 쪽으로 결정**했다 — 노트 목차와 홈도 같은 함정을 겪을 예정이었기 때문이다. 실제로 다음 태스크(노트 배선)에서 그 결정이 §2부 ③의 값을 만들어냈다.

> 국소 수정 vs 셸 수정의 갈림길에서, **"이 함정을 앞으로 몇 번 더 밟을 것인가"**가 판단 기준이다.

### ④ 리뷰가 컨트롤러의 "나중에" 판정을 뒤집었다

노트 본문의 내부 링크가 plain `<a>`라 **클릭마다 전체 페이지 리로드**가 났다. 동작은 정확하니 "나중에"로 미뤄뒀는데, 최종 리뷰가 **빈도를 근거로** 뒤집었다. 실측하니 **20편 전부에 걸쳐 127건** — 리뷰어 추정(96)보다도 많았다. → `RouterLink`로 교체.

### ⑤ 사라질 뻔한 정보를 되살렸다 (2건)

- 제품 상세에서 링크 없는 사내 제품의 액션 영역이 **빈 여백만** 남았다. 구 화면이 렌더하던 **"비공개" 표기가 사라진 정보 후퇴** → 폴백 복원.
- 홈 전면 재작성(+88/−425) 후, 구/신 섹션을 대조하니 **"라이브" 배지가 유실**돼 있었다. 인덱스만 훑는 방문자가 구동 여부를 알 수 없다 → 복원.

> [!note] "사라지는 UI"는 대규모 재작성의 기본 실패 모드다
> 425줄을 지우고 88줄을 쓰면 **테스트도 타입 체크도 통과한다.** 없어진 것을 찾으려면 구/신을 항목 단위로 대조하는 별도 단계가 필요하다.

## 4부. 운영 — 배포까지

이 리포에는 테스트 러너·린터가 없어서 게이트를 이렇게 짰다:

1. `npm run build` — `tsc -b`(strict / noUnusedLocals / noUnusedParameters)가 **타입 게이트**
2. `node scripts/sync-notes.mjs` 검증 리포트 경고 0
3. 정적 링크 감사 — `src/site`+`src/pages`의 모든 `to`/`href` 리터럴이 31개 라우트로 해석되는지(**0건 미해석**)
4. 페이지별 h1 정확히 1개(8페이지), IconButton `aria-label` 2/2, content export 고아 0건
5. 수동: 라이트/다크 × 375/768/1024/1440

**5번은 브라우저 자동화가 안 돼서 사용자가 직접** 했고("잘됨"), 해시 스크롤·스킵링크·다이어그램 판독성·375px 가로스크롤·기존 앱 라우트 회귀를 확인했다.

배포는 [[cicd-pipeline-structure|기존 파이프라인]] 그대로 완주했다:

