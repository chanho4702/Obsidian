# MSA_TEMPLATE — 전체 구조 개요

재사용 가능한 **MSA 레퍼런스 템플릿**. "프론트 → 인증서버 → 백엔드"가 표준 패턴으로 동작하고, 서비스를 하나 더 붙일 때 무엇을 복제하면 되는지가 코드로 드러나는 것이 목표.

## 토폴로지

```
브라우저 ──▶ nginx(:80) ──▶ gateway-server(:8000) ─┬─▶ auth-server(:9000) ──OIDC─▶ Keycloak(:8080)
  / /wiki/ /alm/      API 프록시·단일 오리진      ├─▶ board-service(:9100)
                                           ├─▶ org-service(:9130)
                                           ├─▶ wiki-backend(:9110)
                                           └─▶ search-service(:9140)

내부망:
wiki-backend ──XADD─▶ Redis Streams `platform:events:v1` ──XREADGROUP─▶ search-service
search-service ──gRPC─▶ wiki-backend(:9111)   # 본문·첨부 조달
search-service ──gRPC─▶ org-service(:9131)    # 검색 권한 필터
wiki-backend   ──gRPC─▶ org-service(:9131)    # 스페이스 권한 판정
search-service ──HTTP─▶ OpenSearch(:9200, 호스트 미개방)

백킹: PostgreSQL(:5433) · Redis(:6379) · OpenSearch(내부)
관측: 각 컨테이너 stdout JSON → Alloy → Loki → Grafana(:3000)
```

Docker 배포판은 백엔드 7개 서비스(6개 repo) + 프론트 3개 + 백킹·관측을 포함한 **15컨테이너**다. auth·board는 Docker에서도 Eureka로 찾고, org·wiki·search는 게이트웨이가 Compose DNS URI로 직결하는 하이브리드 디스커버리다.

## 핵심 원칙 (이 설계를 관통하는 결정)

| # | 결정 | 근거 |
|---|---|---|
| 1 | 로그인 = **Keycloak 리다이렉트(OIDC)** + Google. ROPC/자체폼 안 씀 | 표준·SSO. UX 불만은 테마로 해결 |
| 2 | auth-server가 **자체 RS256 JWT** 발급(Keycloak 토큰을 그대로 안 줌) = BFF 패턴 | 프론트 계약을 우리가 통제 |
| 3 | **토큰 검증은 각 리소스 서버가 JWKS로 자체 수행** | 분산 검증. 발급자 1개(:9000), 신뢰는 JWKS로 |
| 4 | 로그아웃 = **백채널**(서버-서버 end_session, KC refresh_token 사용) | id_token_hint 방식은 만료 버그 → [[01 인증 플랫폼 (Keycloak BFF + 자체 JWT)]] |
| 5 | 각 서비스 = **별도 repo**. 우산(infra-settings)은 인프라+구조만 | [[06 저장소 구조 + 운영 원칙]] |
| 6 | 설계/작업 문서는 **Obsidian에만**, repo docs/ 금지 | 〃 |
| 7 | 정본 DB는 **PostgreSQL**, 서비스 간 비동기는 **Redis Streams** | 온프렐 운영 복잡도와 현재 규모에 맞춘 확정 결정 |
| 8 | 애플리케이션은 **stdout JSON**만 출력, Alloy→Loki로 수집 | 로그 전송 결합을 앱에서 제거 |
| 9 | dev 클러스터는 운영 포트 **+10000** | Docker 배포판과 동시 실행. 단 wiki gRPC :9111은 현재 예외 |
