## 2. S-03 마감 — alm-front 레지스트리 전환 (ALM `9525aac`)

wiki-front와 같은 방식(`npm:@chanho4702/*` alias, overrides 두 곳, `minimumReleaseAgeExclude`, setup-node registry-url + `GITHUB_TOKEN`).
CI에서 design-system 체크아웃·tgz 재생성 단계를 제거하고 `--frozen-lockfile`로 복귀. **클린 HEAD 워크트리**에서 게이트를 돌렸다 —
작업 트리에는 다른 세션의 진행 중 변경 46파일이 있었기 때문. 이후 그 세션이 DS 0.8.0/tokens 0.4.0(모달 안 Select 팝업 버그 수정)을 발행하고 alm·wiki 양쪽 버전을 올렸다.

## 3. myFront 노트 동기화 — 번호 중복 가드 (`db25744`)

`sync-notes`를 다시 돌리니 이 시리즈에 **"30 …" 노트가 둘**(온프렘·SaaS 평가 / 위키 파리티 W21)이라 `30.md`와 index 항목이 서로 덮어썼다.
산출물을 지우기 전에 id 중복을 검사해 어떤 파일이 겹치는지 알려주고 멈추게 했다. 다음 날(09-05) 위키 파리티 문서를 **34번**으로 옮기고 29·32·34에 frontmatter를 채웠다. 같은 날 공개 문서 인스턴스 세션이 myFront의 노트 사본·`sync-notes`를 걷어내고 `/tech/notes`를 `/docs/`로 리다이렉트했다 — 이 시리즈는 이제 **위키 docs 인스턴스**(`sync:docs` 임포터)가 게시한다.

## 4. W27 — 컨플·노션 추가 갭 분석과 적용 (wiki-front `742c4dc`, wiki-backend `2a7f17e`)

§3 대조표가 거의 ✅라 **표 밖에 있던 것**을 찾았다. 3레인 서브에이전트(템플릿 / 렌더 확장 / 백엔드)로 병렬 구현.

| # | 기능 | 결정 |
|---|---|---|
| W27-1 | 기본 템플릿 10종(회의록·결정 기록(ADR)·PRD·회고·프로젝트 계획·주간 상태 보고·How-to·트러블슈팅·온보딩 체크리스트·1:1 회의) | **코드에 둔다**(`lib/builtinTemplates.ts`), DB 시드 아님 — 스페이스마다 복제하면 원본을 알 수 없고 전역 테이블은 관리 주체가 모호(V19 주석). 읽기 전용, 설정에서 스페이스 템플릿으로 복사. 10종 전부 마크다운 왕복 검증 |
| W27-1 | 템플릿 변수 `{{date}}` `{{author}}` `{{space}}` | 프론트에서 만들 때 한 번 치환. `{{title}}`은 생성 시점에 "제목 없음"이라 뺐다 |
| W27-2 | 수식(remark-math + rehype-katex) · Mermaid(코드 블록 → SVG) | **보기 렌더에만**. 편집기 스키마(`base.ts`) 무수정 — `$$`·코드 블록은 이미 왕복 안전. mermaid는 별도 청크(683kB) 지연 로드, 다크 테마, 문법 오류 폴백 |
| W27-3 | `::pages-by-label[라벨]` · `::recently-updated{limit=N}` | `::excerpt-include` 선례대로 placeholder div → 컴포넌트가 스토어 조회. 슬래시 메뉴 4항목 추가 |
| W27-4 | 스페이스 구독 | V32 `space_watch`. 알림 대상 = 페이지 구독자 ∪ 스페이스 구독자(중복 없음, effective VIEW 필터). 새 문서 게시는 `PAGE_PUBLISHED`로 **구독자만**(멘션을 넣으면 "문서 생성은 멘션 트리거가 아니다"는 결정을 뒷문으로 뒤집게 됨). 자동 구독 없음 |
| W27-5 | 페이지 소유자·검증 | V33 `owner_id/verified_at/verified_by/verified_until`. 소유자는 표시일 뿐 권한과 무관, 기본값 없음(created_by 복사 안 함). `verifiedUntil`은 날짜만 — 만료 판정은 화면(타임존 흔들림 방지). 편집해도 검증은 안 풀린다(정책 미정, 임의 판단 안 함) |

게이트: wiki-front typecheck·1050 테스트·프로덕션 빌드, wiki-backend gradlew 342(+Flyway 스키마 Testcontainers).

범위 밖: 스페이스 카테고리·아이콘 색(디렉토리 필터 UX 선행), 노션 DB·오프라인·화이트보드(확장 트랙), Jira 매크로(ALM 트랙).
남긴 것: 빈 스페이스는 헤더 대신 EmptyState라 구독 토글이 없음 · 복제 문서는 검증·소유자 초기화(목업 실측) · 편집 시 검증 해제 정책 결정 필요.

## 5. 병렬 세션 조율 (처음 겪은 것)

- alm-front: 다른 세션(msa-template-06)이 UI/UX 배치 중. S-03 파일만 골라 커밋했고, 그 세션이 DS 0.8.0 범프를 자기 커밋에 넣기로.
- wiki-front: 제3 세션(msa-template-2e)이 **공개 문서 인스턴스(로그인 없는 읽기 전용 `/docs/`, `--mode docs`)** 를 같은 트리에서 구현 중.
  PageViewPage·AppShell·main.tsx 등에 두 작업 헝크가 섞여 한쪽만 커밋하면 HEAD가 컴파일되지 않는다(untracked import).
  합의: 각자 게이트 그린 → 내가 W27 커밋(공유 파일 현재 상태 포함) → 그쪽이 읽기 전용 커밋 → 최종 게이트 → **한 번의 푸시**.
  중간 커밋 하나가 단독 컴파일 안 되는 건 감수(push 이벤트 CI는 tip만 돈다).
- 교훈: 같은 리포를 두 세션이 만질 땐 **시작할 때** 파일 경계를 나누는 게 낫다. 끝에 헝크 단위로 가르는 건 안 된다.
