## 결론

**아키텍처 방향은 좋지만 구현 완결성과 운영 복원력 사이에 간극이 있다.** Keycloak OIDC 위임, 자체 RS256 JWT, 서비스별 JWT 검증, Gateway 단일 진입점, PostgreSQL 정본 + Redis Streams 파생 이벤트, stdout JSON + Alloy→Loki라는 큰 방향은 일관적이다. 다만 Wiki를 중심으로 프론트↔백엔드 계약, 파일·DB 원자성, 내부 gRPC 신뢰 경계, 이벤트 재전송, 전 서비스 로그 규약이 아직 템플릿 수준으로 닫히지 않았다.

### - [ ] M-07 · DB outbox→Redis Streams 재전송 경로 추가

- **심각도:** major

- **설계 경계:** PostgreSQL 정본 + Redis Streams라는 확정 결정을 바꾸지 않는다. DB outbox를 영속 재시도 계층으로 추가한다.
- **완료 조건(DoD):**
  - [ ] 도메인 변경과 outbox row가 같은 DB 트랜잭션에 커밋된다.

  - [ ] Redis 중단→여러 변경→복구 시 누락 없이 Streams에 도달하는 통합 테스트가 있다.
  - [ ] outbox 적체량·최고 지연·실패 횟수에 메트릭/경보를 둔다.
