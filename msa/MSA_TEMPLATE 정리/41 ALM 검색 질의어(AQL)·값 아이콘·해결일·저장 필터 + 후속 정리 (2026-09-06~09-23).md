## 1. AQL — JQL식 이슈 질의어 (09-06)

**결정**: 전송은 REST(`POST /api/alm/issues/query`·`/validate`·`GET /fields`). 플랫폼 GraphQL은 위키·search-service 전용이라 쓰지 않고, 실행은 alm-backend JPA Criteria라 OpenSearch가 필요 없다. 문법은 JQL 그대로(필드 연산자 값, AND/OR/NOT, 괄호, IN, `~`, 상대 날짜, ORDER BY)에 **한국어 별칭**(`상태 = 완료 AND 담당자 = 김찬호`)을 얹었다.

**양쪽 파서, 하나의 AST**: 서버(`search/aql/` 재귀 하강)와 프론트(`store/aql/`)가 같은 AST JSON을 내야 한다. 명세 §6 벡터 7개를 양쪽 테스트가 **문자열로** 고정(키 순서까지)해 리뷰어가 바이트 단위 일치를 기계 대조했다. 프론트 파서는 필드 표를 모르는 순수 문법이고 검증은 별도 단계 — 서버와 같은 구조.

**확정 의미**(둘 다 동일): `!=`·`NOT IN`·`!~`는 JQL대로 EMPTY 제외, `NOT(…)`은 여집합 / 라벨은 정확·대소문자 구분 / 날짜 경계 Asia/Seoul·월요일 시작(CI가 UTC라 프론트 목업도 고정) / 보관 이슈는 `archived` 언급 없으면 제외 / org 디렉터리 불능은 503(빈 결과로 바꾸지 않음) / 우선순위 비교는 레지스트리 순서.

**리뷰가 잡은 것**: 괄호 재귀 상한 없음 → 깊이 5000에서 `StackOverflowError`가 500으로 샘(실측) → 깊이 50·절 200·4000자 상한, 모두 400 `{error, position, expected}`. `~`가 LIKE `%`·`_`를 이스케이프하지 않음 → `text ~ "%"`가 전체 매치. 프론트는 AQL 결과가 200건에서 조용히 잘리면서 머리글은 서버 total을 보여줌 → 50건 페이징(범위+이전/다음). 날짜 리터럴 `2026-13-99`가 다음 해로 굴러가던 것도 이때 발견.

**못 한 것 → §3에서 해소**: `resolved` 필드(해결 시각 컬럼 없음), 저장 필터 서버 저장.

커밋: alm-backend 7771630·9372838(221 테스트), alm-front 645da51.

## 2. 값 아이콘+텍스트 전면 적용 (09-06)

타입·상태·우선순위·해결 **값**은 어디서든 아이콘+텍스트(색만으로 구분하지 않음). DS `Select` 옵션이 문자열 라벨뿐이라 design-system을 두 번 발행: **react 0.10.0** `SelectOption.icon`(목록·트리거 양쪽, `aria-hidden`), **0.11.0** `Checkbox/Switch/Radio label: ReactNode`(+`aria-labelledby` 자동 배선). alm-front: Select 옵션 13곳·체크박스 라벨 5곳·표/칩/카드/설정 목록 12곳·검색 필터·전역 검색 후보, 새 `ResolutionGlyph`·`ValueWithIcon`(새 CSS 0줄).

**접근성 규칙 하나가 생겼다**: 글리프 옆에 같은 이름 텍스트가 붙는 자리(옵션·체크박스·라디오·탭·값 셀)는 `variant="icon"` — 안 그러면 접근 이름이 "상태: 할 일 할 일"로 겹친다. 보드 컬럼 머리글만 기존 테스트 계약(`role=img` + 이름) 때문에 예외. 커밋 alm-front a7bb65a(763 테스트).

## 3. 해결일·저장 필터 서버 저장 + 정리 (09-12)

- **해결일 `resolvedAt`**(alm-backend V23, 백필 `resolution IS NOT NULL → updated_at`): resolution이 **처음** 붙을 때 기록, 사유만 바꾸면 불변, 해제하면 null — `Issue.applyResolution` 단일 경로. AQL `resolved`(해결일) 지원, 이슈 상세에 "해결일". 리뷰: 되돌릴 수 없는 백필에 테스트가 없었다 → Testcontainers에서 V22→V23 실증 테스트 추가.
- **저장 필터**(V24 `saved_filter`, `/api/alm/me/filters` CRUD, 소유자 격리는 리포지터리 수준, aql은 저장 시 문법 검사): 프론트는 파사드 4함수, 목업은 기존 localStorage 키 호환, REST 첫 조회 때 1회 이관. 리뷰: 옛 로컬 필터가 빈 질의면 이관 400이 목록 조회 전체를 영구 차단 → 4xx는 그 건만 스킵·5xx는 보존·목록은 절대 실패시키지 않음; 사이드바가 503을 "필터 없음"으로 보이게 하던 것 → 실패 문구+다시 시도.
- **정렬 함정**: 서버는 Java `Collator(ko, PRIMARY)` = 숫자→영문→한글인데, 브라우저 ICU의 "ko" 대조는 한글을 라틴 앞으로 재배치한다. 프론트 목업은 `Intl.Collator("en")`로 서버 순서를 맞췄다(주석에 근거).
- 정리: `PreferenceService`의 메일 상태 HTTP를 읽기 트랜잭션 밖으로, 미정의 토큰 4개 치환, 데모 시더 진행바.

커밋: alm-backend 98b2336·93d3737(261 테스트), alm-front 8a494ec(799 테스트/91 파일).
