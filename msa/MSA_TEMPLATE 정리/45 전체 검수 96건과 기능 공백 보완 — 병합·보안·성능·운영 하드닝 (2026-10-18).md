## 1. 오늘의 순서
1. **미병합 브랜치 정리** — 10-16 피처 브랜치(위키 검색 권한·쪽 목록, ALM 무결성·성능, 배포 하드닝)를 게이트를 돌린 뒤 main에 병합·배포했다. 9-30에 하다 멈춘 P4c(AI 사무실 실시간 스트림)도 마무리했다.
2. **검수 4갈래**(읽기 전용): 위키 24건 · ALM 23건 · 플랫폼 코어 24건 · 에이전트/운영/문서 25건.
3. **기능 공백 분석**(기획): 25건(P0 3 · P1 15 · P2 7).
4. **리포별 엔지니어 병렬 작업** → 각 결과를 **Codex 교차검증** → 지적 수정 → 게이트 → main 배포.
5. **교차 보안 단계 배포** — gRPC 토큰 monitor → 전 서비스 토큰 송신 → enforce.

## 2. 사용자 결정 (이번에 확정)
- 위키 초안은 **작성자 + 스페이스 ADMIN + 전역 ADMIN**만 본다. 게시 전에는 알림·검색에서 뺀다(확정 결정에 추가).
- 서비스 간 gRPC는 공용 토큰 `PLATFORM_GRPC_TOKEN`으로 검사한다. 구성원 비활성은 org가 auth로 전파한다(확정 결정에 추가).
- 운영 조치는 코드·가드·런북·백업 예약까지만 Claude가 하고, **실제 비밀번호 교체는 사용자**가 런북대로 한다.
- 리팩터링은 적극 분할한다.
- 저장 필터 공유 범위는 조직 전체이고, 결과는 보는 사람 권한으로 거른다.
- 사람 프로필의 이메일·팀은 구성원 전원에게 보인다(F-07은 P2라 이번엔 미구현).
- 에이전트 예산 상한은 플랫폼 + 프로젝트별(F-19는 P2, 모델이 막지 않음만 확인).

## 4. 오늘 겪은 사고와 교훈
- **배포 게이트 오탐 → 자동 롤백 3건**(wiki·alm·agent). 내가 테스트·Codex·빌드를 동시에 돌려 Docker CLI(`compose ps`/`docker exec`)가 5초 안에 응답하지 못했다. 메모리 상한 적용 뒤라 JVM 기동도 느렸다. 롤백 자체는 잘 동작했고 DB 마이그레이션은 호환이었다.
  - 교훈: **무거운 테스트와 배포를 겹치지 않는다.** 게이트 상한은 240초로 늘렸다.
  - 함정: 배포 직후 잠깐 healthy로 보인 것을 성공으로 오인했다. **배포 워크플로 결론(success)으로 판정**한다.
- **Testcontainers·vitest 실패 대부분이 부하 타임아웃**이었다. 실패 파일만 단독으로 재실행해 판정했고, 진짜 결함은 ALM 1건(테스트 기대치)과 ArchiveTrash 타이밍 테스트였다.
- Codex는 매 리포에서 실제 결함을 2~4건씩 더 잡았다. 많이 나온 유형은 커서가 숨은 행 뒤에서 멈추는 문제, 권한 경계 메타데이터 누출, 404를 "없음"으로 오인하는 문제다.
- 프론트가 목업 규칙을 먼저 만들면, 백엔드가 같은 경로를 빠뜨리지 않는지 체크리스트로 넘긴다(초안 가시성의 라벨·조상·공유 경로).

## 5. 사용자 몫으로 남은 것
1. **비밀번호 교체**(런북 `infra/runbooks/` 비밀번호 교체): DB·Keycloak admin·KC 서비스계정·MinIO·Grafana·OIDC 시크릿. 운영 realm의 platform-admin 시크릿이 `$(env:…)` 글자 그대로일 가능성이 있다(옛 import 문법). 교체 뒤 `PLATFORM_DEFAULT_SECRETS_POLICY=enforce`, `REQUIRE_STRONG_SECRETS=true`.
2. Keycloak `start`(프로덕션 모드) 전환, 데모 계정(admin/admin·alice) 비활성화, 자가가입 끄기 여부, `KC_HOST_BIND=127.0.0.1`.
3. 전체 DB 9개 정합 백업은 쓰기 중단이 필요해 수동이다(예약은 ALM만). 오프사이트 복원을 증명하면 보존 기간을 정한다.
4. 브라우저로 새 화면 확인: 위키 `/my`·`/notifications`·`/settings/watches`, ALM 공유 필터·이슈 복제·스프린트 삭제, `/app` AI 카드·킬 스위치·토큰 관리.
