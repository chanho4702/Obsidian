## 1. 무엇을 고쳤나

- **검색 누락(A)** — 예전엔 후보를 500건으로 자른 뒤 권한을 걸러, 앞쪽이 전부 제한 문서면 0건이었다. 이제 볼 수 없는 페이지 집합을 먼저 구해 SQL에서 빼고 센다(정확한 total). 숨길 문서가 1000건을 넘으면 본문 없는 키를 최대 1만 건 읽어 거르고, 넘치면 "N건 이상"(`totalExact=false`). 본문을 읽은 뒤 권한 재판정, 질의 뒤 숨김 집합이 바뀌면 다시 계산, 다른 스페이스에 있는 조상의 제한도 반영. 권한 캐시는 넣지 않았다(회수 즉시 반영).
- **과조회(B·C)** — 트리·이력 목록이 `content`/`content_gzip`을 안 읽는다(Hibernate 통계 테스트로 회귀 방지). 같은 제한 조회 2회→1회, 댓글 삭제가 페이지 댓글 전량을 안 읽는다.
- **쪽 목록(D)** — `GET /pages/{id}/revisions/paged`(50개씩), `GET /pages/{id}/comments/threads`(스레드 20개씩, 커서). 기존 전량 API는 유지. 화면은 "이전 버전 더 보기", "이전 코멘트 N개 더 보기".
- **알림(E)** — 보이는 탭에서 60초 주기, 탭 복귀·포커스 때 바로(10초 간격), 요청 하나만·30초 넘으면 끊고 다시, 실패 시 최대 5분 백오프.
- **스페이스 라벨(F)** — V41 `space_label`, `PUT /spaces/{id}/labels`(ADMIN, 최대 10개). 디렉토리 라벨 칩·`?label=` 필터, 설정 화면 편집기.

## 2. PostgreSQL 실측에서 나온 것

> [!note] 왜 H2만으로는 부족한가
> 테스트 대부분은 H2 + `create-drop`이라 Flyway 마이그레이션도, PostgreSQL 전용 동작도 타지 않는다. 그래서 운영 DB에서만 터지는 결함이 CI를 통과한다.

- **라이트 검색이 PostgreSQL에서 통째로 실패**(main에도 있던 결함) — pgjdbc는 시각 타입 null을 타입 미지정으로 보내서 `(:after is null or …)`를 PostgreSQL이 거부했다. 날짜 필터 없는 검색이 기본이라 `SEARCH_MODE=lite` 전체가 막혀 있었다(배포 환경은 opensearch라 안 보였다). `cast(:after as java.time.Instant)`로 수정, `FlywaySchemaValidationTest`에 회귀 테스트(`475fc62`).
- **블로그 글 저장 불가** — `page_type_check`에 BLOG가 없었다. 10-18 V42로 해소.
- V41·새 질의·새 테스트(쪽 목록 7, 라벨 4, 검색 25)는 PostgreSQL 16에서 통과.

## 4. 남은 작업

1. **H2 전제 테스트 픽스처 정비** — 전체 스위트를 PostgreSQL로 돌리면 10-16 기준 24건이 main과 똑같이 실패했다(BLOG 2건은 V42로 풀렸을 것). 원인은 대부분 테스트 데이터가 H2 기준인 것: `CollaborationDraftCommitTest`·`CollaborationDraftResetTest`(collaboration_document NOT NULL 열 누락), `WikiImportApiTest`, `TaskApiTest`(유니크), `TrashTest`, `WikiContentGrpcServiceTest`(FK). 이후 이 테스트 파일 중 다섯 개가 다른 이유로 수정됐다(10-18 검수·리팩터) — 지금 몇 건이 남았는지는 PG로 다시 돌려 확인해야 한다. 고치고 나면 **CI에 PG 전체 스위트 잡을 두는 것**이 근본 대책(지금 CI의 PG 검증은 `FlywaySchemaValidationTest` 하나).
   - 돌리는 법: 임시 `postgres:16-alpine` 컨테이너 + env `SPRING_DATASOURCE_URL`·`SPRING_DATASOURCE_DRIVER_CLASS_NAME=org.postgresql.Driver`·`SPRING_FLYWAY_ENABLED=true`·`SPRING_JPA_HIBERNATE_DDL_AUTO=validate`로 `./gradlew test --continue`.
2. **응답 시간 실측** — 검색·트리·이력 API와 DB 질의 시간을 재지 않았다. 개선율 수치는 없다. 검색은 정확한 total을 위해 COUNT 질의 1개, 제한 있는 스페이스에서는 숨김 집합 재계산 1회가 늘었다 — 소규모 기준 괜찮다고 판단했지만 실측 필요(`pg_stat_statements` 또는 k6).
3. **목업 `setSpaceLabels`의 ADMIN 검사**(minor) — Codex 지적. 목업은 스페이스 이름 변경·삭제에도 역할 검사가 없어 일관성상 두었다. 하려면 목업 관리 작업 전체에 함께.
4. ~~**병합 끝난 원격 피처 브랜치 2개**~~ — 2026-11-01 원격·로컬 모두 삭제 완료.
5. **위키 '개발' 스페이스 정본·ALM(WIKI 프로젝트) 이슈 등록** — 10-25 결정(위키 정본 + Obsidian 복사)에 따라 이 문서를 위키에 올리고 1·2번을 이슈로 만들어야 한다. 이 기록을 쓴 세션에는 플랫폼 MCP가 연결되지 않아 Obsidian에만 썼다.
