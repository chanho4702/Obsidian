## 1. 왜 이 구조인가

사내망은 "누가 최종 배달하느냐"가 핵심이다. (1) 회사 SMTP가 있으면 **릴레이**, (2) 인터넷 발송이 되면 직접 배달이나 외부 SMTP 릴레이, (3) 완전 폐쇄망이면 우리 스택이 MX. 이걸 설치 옵션 하나(`MAIL_MODE`)와 발송 관문 하나(org-service)로 덮었다. 전에는 org 초대·위키·ALM이 각자 JavaMail + `*_MAIL_*` env를 가졌고(접두사·미설정 처리·수신자 정책 제각각), `.env`엔 메일 키가 하나도 없어 전부 꺼져 있었다.

## 2. 설치 옵션 (infra d784006·bd1d238 — compose `profiles:` 첫 도입)

| MAIL_MODE | 컨테이너 | 시드 | 언제 |
|---|---|---|---|
| none | 없음 | enabled=false | 메일 없이(초대는 링크 복사) |
| external | 없음 | `MAIL_SEED_*` = 사내/외부 SMTP | 기존 메일 시스템 사용 |
| relay | `mail-relay`(boky/postfix v4.4.0, profile mail-relay) | host=mail-relay:25 | `MAIL_RELAY_HOST`(host:port) 비면 직접 배달, 채우면 릴레이 |
| full | `mail`(docker-mailserver 15.1.0, 25/465/587/993, rspamd) | host=mail:587 STARTTLS | 완전 폐쇄망, `mail-setup.ps1`이 계정·DKIM·DNS 출력 |
| dev | `mailpit`(v1.30.0, UI 127.0.0.1:`MAILPIT_UI_PORT`) | host=mailpit:1025 | 캡처만 |

- `scripts/mail-up.ps1 [-Mode]`(생략 시 `.env` MAIL_MODE, 모드 전환 시 다른 모드 컨테이너 내림), `mail-setup.ps1`(full). smoke 8c: 모드↔시드 호스트 대조, 옛 `*_MAIL_HOST` 잔존 FAIL, `ORG_INTERNAL_TOKEN` 4서비스 동일, 키 형식; 라이브: 관문 running/healthy·타 모드 잔존 FAIL.
- 함정: Windows 동적 포트 예약 구간에 8025가 걸림 → `MAILPIT_UI_PORT=18025`. 프로필 서비스는 프로필 없는 `compose config`에 안 나오므로 `$mustBeHealthChecked`에 넣지 않는다(§9는 `compose ps`로 본다).

## 3. org-service 메일 허브 (platform-backend 55b5078, 193 테스트)

V8 `mail_setting`(1행, 비밀번호 AES-GCM `ORG_SETTINGS_ENC_KEY` 없으면 저장 400) + `mail_outbox`. 워커 5초 폴링·배치 20·JPA 비관적 잠금(PG `for update skip locked`)·지수 백오프 5회 → FAILED·30일 정리. 관리 API `/api/org/settings/mail`(GET/PUT·test·log·log/{id}/retry, 전역 관리자), 내부 `POST /internal/org/mail`(`to`≤100, 202 `{accepted, disabled}`)·`GET /internal/org/mail/status`(`enabled`="실제 발송 가능"). 초대 메일은 outbox 경유 → `mailSent`는 "큐에 넣었다". `PLATFORM_MAIL_*` 제거.

## 5. 실측 (dev/Mailpit, 이 머신)

`.env`+`C:\deploy\platform.env`에 MAIL_MODE=dev 블록·ENC 키. org 허브 E2E **8/8**: 설정 조회(시드 mailpit:1025)·테스트 발송 ok·Mailpit 도착·초대 mailSent=true→outbox SENT→Mailpit 도착·내부 API 외부 미노출(nginx 405)·비관리자 403. 위키 컨테이너는 첫 배포가 옛 compose env로 떠서 재배포로 `ORG_INTERNAL_*` 주입(§6).
