# 29. 위키 컨플·노션 동등성 스프린트 — 에디터·사이드바·알림·백엔드 V8~V11 (2026-08-23)

## 1. 에디터 — 블록·서식 동등성

| 기능 | 저장 문법(확정) | 비고 |
|---|---|---|
| 토글(expand) | `:::details[제목]` 컨테이너 | 편집 기본 펼침 / 보기 기본 접힘. 접힘 상태는 저장 안 함 |
| 사용자 멘션 | `[@이름](user:id)` 표준 링크 | org 디렉터리 자동완성, 신규 문법 없음 |
| 날짜 요소 | `[ISO](date:ISO)` + `//` 캘린더 | DatePickerPopup, Enter=오늘 |
| 글자색/배경색 | `:c[내용]{.red}` / `:bg[내용]{.yellow}` 텍스트 지시자 | **9색 팔레트**(노랑=황토 톤 4.5:1, 청록, 자홍 추가). 임의 hex 금지 |
| 표 셀 병합 | 마커 셀 `<<`(colspan)·`^^`(rowspan) | GFM 파이프 구조 유지 — 모르는 렌더러에선 마커 문자만 보이는 열화 |
| 표 셀 배경 | 셀 접두 `{.bg-색}` | 선택 셀 일괄 적용(setCellAttribute) |
| 표 헤더 열 | 셀 접두 `{.th}` | toggleHeaderColumn, 보기는 th[scope=row]. 색 마커와 조합 가능 |
| 링크 카드 | `::bookmark{url="…" title="…"}` 리프 지시자 | URL 붙여넣기 → URL/인라인/카드 전환 메뉴 |
| 패널(alerts) | 기존 `[!NOTE]` 유지 | 편집 화면도 마커 숨김+아이콘, 커서 진입 시 5종 스위처 |
| 이미지 | `#w=` URL 프래그먼트(폭)·title(캡션) | 리사이즈 핸들 + 캡션 입력 |

핵심 패턴(재발 방지용):
- **markdown-it 인라인 중첩 파싱은 반드시 새 배열로** — `state.tokens`에 직접 파싱하면 바깥 emphasis 델리미터와 엉켜 `**:c[..]{.red}**`에서 여는 태그가 소실된다(실측 버그).
- **표 마커의 보기 렌더는 remark가 아니라 rehype 단계** — remark-gfm의 hast 변환이 행을 열 수에 맞춰 빈 셀로 패딩해 mdast에서 지운 셀이 되살아난다(실측).
- 편집(tableSpanBridge fold/expand)과 보기(rehypeTableSpans)가 **같은 그리드 알고리즘**(lib/tableSpans.ts)을 공유해야 두 화면이 안 어긋난다.
- 색·마커 판정은 팔레트 셋(isTextColor/isBgColor) 하나로 — 팔레트 확장이 전 경로(편집/보기/셀)에 자동 전파된다.

UI/UX(컨플 캡처 페이지기본·페이지편집.png 기준):
- 편집 레이아웃: 툴바 줄 **전체 너비 고정**, 큰 제목(+이모지 버튼)은 툴바 아래 콘텐츠 칼럼(WikiEditor `contentHeader` 슬롯). 기본/전체 너비 토글은 콘텐츠 칼럼만 조절.
- 표 컨트롤: 상단 고정 줄 → **표 바로 위 플로팅 바**(불합격 피드백: 컨트롤은 대상 옆에 있어야 발견된다).
- 색상 피커: 컨플식 스와치 그리드(5열·8px 간격·기본 칩·✓ 표시) + TopToolbar "가" 스플릿 버튼(최근 색 밑줄·원클릭 재적용, localStorage 유지).
- 슬래시 메뉴 단축키 뱃지 + Mod-Alt-d/t/p, `//` 캘린더, 단축키 도움말 모달(표기 단일 원천 = slashMenu.shortcut).
- 라이브 TOC(`::toc` 위젯) + 우측 레일 스크롤스파이, 목차 중복 방지(본문에 ::toc 있으면 자동 목차 숨김).

## 2. 사이드바·셸

- 트리 ⋯ 메뉴: **인라인 이름 바꾸기**(모달 아님 — 행이 입력으로, Enter/blur 저장·Esc 취소. 드롭다운 포커스 복원과의 blur 경합은 rename 진입을 다음 틱으로 미뤄 해소), 링크 복사(base `/wiki` 포함), 별표 표시/해제, 복제, 이동(스페이스 간 + 하위 처리 선택).
- 페이지 이모지: Page.icon — 편집 제목 옆 EmojiPicker(onPick/onClear 확장), 트리·별표 패널에서 문서 아이콘 대체, 설정 즉시 reloadPages.
- 별표 = **검색형 플라이아웃**(펼침 목록 아님 — 사용자 지시). starredPages v2: 별표 시점 {id, spaceId, title, icon, type} 스냅샷 + hydrate(개명 반영) + v1 문자열 배열 호환.
- 조회수: 보기 진입 시 기록, 메타 라인 "조회 N회".
- 만들기: 헤더 메뉴에 "위치 지정해 만들기…"(타입+제목+스페이스+상위 위치), 홈·디렉토리 헤더에서도 생성 가능.
- TopBar: 알림 벨(배지+알림함 팝오버), 설정 드롭다운(다크모드·단축키), 사용자 메뉴. 사이드바 Jira 링크 제거.
- 스켈레톤 UI 전면(스피너 제거), 트리 조작 시 페이지 전체 리로딩 없음(suppressNavRef).

## 3. wiki-backend V8~V11

| 버전 | 내용 |
|---|---|
| V8 | page_comment(1단 답글, author_name 스냅샷) |
| V9 | page.sort_order — 형제 순서 서버 저장(그룹 잠금 아래 1..n 조밀 재부여, ALM과 동형) |
| V10 | page.icon(varchar16) + view_count. PUT /icon(EDIT, 버전 불변), POST /views(VIEW, **원자 UPDATE** — dirty-check 증가는 동시 조회 lost update) |
| V11 | notification(user_id, type, page_id, actor_id, read_at). GET /notifications {unreadCount, items(+spaceId·pageTitle)}, POST /read |

알림 규칙(사용자 스펙+재량): 새 멘션=MENTIONED(합침 없음), 관심 사용자(작성자+리비전 편집자+본문 멘션)=PAGE_UPDATED/COMMENT(같은 수신자·페이지·타입 미읽음은 시각만 갱신해 1건 합침), **행위자 자신 제외**. 저장 트랜잭션 내 동기 기록(M 규모 — 큐 분리는 과잉). 권한 필터는 W18 effective permission에서 합류.

성능(규모 검토 즉시 반영): 트리 API 프로젝션(본문 text 미로드 — 최대 전송 낭비 제거), collectSubtree N+1 → 스페이스 (id,parent_id) 1쿼리+메모리 BFS.

기타: cross-space move(하위 with/promote, 스페이스 잠금 id 순서), copy(첨부 복제+inline URL 재작성), Page.spaceId의 `updatable=false` 함정(더티체킹 무음 무시) 제거.

## 4. 설계 문서(리포에 커밋)

- `wiki-front/docs/superpowers/specs/2026-08-23-w18-page-restriction-design.md` — 권한 상세 설계: page_restriction 모델(행 없음=제한 없음, USER/TEAM), effective permission 단일 함수(space 선행 fail-closed → 조상 VIEW 교집합 상속 → 현재 페이지 EDIT, ADMIN은 관리만), 검색 질의시점 후필터(visible 배치 API), 이동 영향 2단계 확인, 누출 테스트 매트릭스, **4증분 구현 순서**.

## 6. 이날의 프로세스 교훈

- 사용자 지시 스타일: 짧은 구어 피드백이 mid-turn으로 계속 들어옴 — 태스크로 즉시 등록하고 완료 후 커밋 단위로 정리하는 흐름이 잘 맞았다. "지시가 애매하면 되물을 것" 명시 지시 받음(메모리 저장).
- 불합격 재작업의 원인은 기능 부재가 아니라 **발견성**(표 컨트롤이 표에서 멀리) — 컨트롤은 대상 옆에.
- 테스트 이관 사례: 제목 입력이 에디터 콘텐츠 칼럼으로 들어가며 리마운트 → 캡처해 둔 DOM 노드 재사용 테스트는 재쿼리로 이관(약화 아님).
