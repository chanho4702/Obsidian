# myFront 기업형 리뉴얼 + 옵시디언 노트 게시 — 설계

## 1. 배경과 목표

`myFront`는 현재 `/` 단일 랜딩 페이지에 히어로 → 커리어 → What I do → 제품 → 케이스스터디 →
스택 → 연락이 세로로 쌓인 **개인 포트폴리오**다. 상세 라우트(`/services/:slug`,
`/products/:slug`)는 존재하지만 본문이 전부 "상세 내용은 준비 중입니다" 플레이스홀더다.

목표는 이것을 **1인 기술 스튜디오 성격의 기업형 사이트**로 재편하는 것이다. 구체적으로:

- 원페이지 → 목적별 멀티페이지(제품 / 기술 / 소개 / 연락)
- "준비 중" 제거 — 제품 상세에 실제 스펙을 채운다
- 기술 페이지의 본문을 옵시디언 볼트의 `MSA_TEMPLATE 정리` 00~19 시리즈로 채워
  엔지니어링 노트(사내 기술 블로그) 포지션을 만든다

**비목표**: 가상 법인 서술("우리는", 팀·연혁·고객사)은 만들지 않는다. 1인 실체와 서술이
어긋나면 채용·영업 상황에서 과장으로 읽힌다. 톤은 1인칭 사실 기반을 유지하고, 기업다움은
정보구조·타이포·섹션 밀도로만 낸다.

## 2. 확정된 결정 사항

| 항목 | 결정 | 근거 |
|------|------|------|
| 기업화 수위 | 1인 스튜디오/랩 | 가상 법인 톤은 1인 실체와 충돌 |
| 시각 언어 | 엔지니어링 그리드 (헤어라인·모노 라벨·수치 전면) | 기술 신뢰감 최대, 기존 플랫 팔레트·다크모드와 정합 |
| 콘텐츠 소스 | 실제 리포에서 사실 추출해 작성 | 검증 가능한 사실만 게시 |
| 옵시디언 연동 | 빌드타임 동기화 (스크립트 → 번들) | 네트워크 의존 0, 검색·SEO 가능, CI 빌드 재현성 |
| 공개 범위 | `MSA_TEMPLATE 정리` 00~19 만 | 개인 준비물(면접 방어 시트 등) 구조적 배제 |
| 노트 URL | 번호 slug (`/tech/notes/07`) | 한글 URL 인코딩 회피 + 제목 변경에도 링크 유지 |
| 신규 의존성 | react-markdown, remark-gfm, rehype-slug 3개 | 승인됨 |

팔레트(스틸 블루 `#1B66C9` + 쿨 그레이)와 서체(Pretendard)는 **변경하지 않는다**.
`ui-ux-pro-max`가 이 제품 유형에 추천한 팔레트는 "네이비 + 블루 CTA"로 현행과 사실상 동일했고,
추천 서체(Lexend / Source Sans 3)는 한글 지원이 없어 Pretendard 유지가 옳다.
추천 패턴은 Enterprise Gateway + Flat Design이며 아래 IA·시각 시스템이 이를 1인 규모로 축소 반영한다.

## 3. 정보구조 (IA)

```
/                   홈 — 게이트웨이형 랜딩. 요약과 유입만 담당
/products           제품 인덱스 (오픈소스 4 + 디무브 2)
/products/:slug     제품 상세 — 스펙 테이블 · 아키텍처 · 링크
/tech               기술 — 플랫폼 구성 · 역량 4 · 스택 · 노트 진입
/tech/notes         엔지니어링 노트 인덱스
/tech/notes/:id     노트 본문 (id = 00~19)
/about              소개 — 커리어 타임라인 · 케이스스터디 3 · 수상
/contact            연락
```

**기존 라우트 처리**

- `/services/:slug` (4개) → `/tech#cap-<slug>` 리다이렉트. 죽은 링크를 만들지 않는다.
- `/app` `/designs` `/profile` `/templates` `/components` `/showcase` `/sign-in` 계열은 유지하되
  GNB에서 제거하고 푸터 "개발 도구" 그룹으로 격리한다. 현재 GNB에 위키·ALM·설계문서·프로필이
  섞여 있어 기업 사이트로는 산만하다.
- 위키(`/wiki/`)·ALM(`/alm/`)은 nginx 단일 오리진의 별도 SPA이므로 계속 전체 페이지 이동
  링크로 두되, GNB가 아니라 `/products` 안의 해당 제품 카드에서 진입시킨다.

**GNB**: 제품 / 기술 / 소개 + `문의하기`(contained CTA). 현재 라우트를 활성 표시한다.

## 4. 시각 시스템 — 엔지니어링 그리드

| 규칙 | 내용 |
|------|------|
| Elevation | `box-shadow` 전면 미사용. 1px `divider` 헤어라인만으로 구분 |
| Radius | 8px → 4px |
| 섹션 | 좌측 고정폭 모노 라벨 컬럼(`SEC.02 / PRODUCTS`) + 우측 콘텐츠, 상단 헤어라인 |
| 수치 | `font-variant-numeric: tabular-nums` 강제. 스탯바로 전면 노출 |
| 인터랙션 | hover = `border-color` 150ms 전이만. `translateY` 이동 제거(레이아웃 안정) |
| 모노 라벨 | letter-spacing 0.14em, 대비 검증된 전용 톤(`text.secondary` 그대로 쓰지 않음) |
| 다크모드 | 헤어라인이 `divider` 토큰이라 자동 대응. 대비는 라이트/다크 각각 실측 |

**신규 프리미티브** `src/site/ui/`

- `SectionLabel` — `SEC.02 / PRODUCTS` 모노 라벨 + 헤어라인 룰
- `GridSection` — 라벨 컬럼 + 콘텐츠 2열 레이아웃 셸 (모바일에서는 세로 적층)
- `SpecTable` — key/value 스펙 테이블. 제품 상세·기술 페이지 공용
- `StatBar` — 수치 4칸 (장관상 2 · 사이트 30 · 이력 이관 3,000건 · 서비스 6)
- `HairlineCard` — 그림자 없는 아웃라인 카드

페이지들은 이 프리미티브만 조합한다. 일관성을 리뷰가 아니라 코드로 강제하기 위한 경계다.

**접근성 (WCAG AA)**

- 본문 대비 4.5:1, 라이트/다크 각각 측정
- `:focus-visible` 링 유지, 제거 금지
- hover 단독으로 정보를 전달하지 않음 (제품 카드의 상태는 텍스트로도 표기)
- `prefers-reduced-motion` 존중 — 전이 무효화
- 헤딩 위계 h1 → h2 → h3 건너뛰지 않음, 페이지당 h1 하나

## 5. 콘텐츠 계층

`src/pages/landing/content.ts` 단일 파일 → `src/site/content/`로 분리한다.
현재 케이스스터디·커리어·스택이 `Home.tsx`에 인라인 상수로 박혀 있어 페이지가 늘면
중복이 생긴다.

```
src/site/content/
  products.ts       제품별 스펙 — 스택 · 아키텍처 요약 · 상태 · 하이라이트 · 링크
  capabilities.ts   역량 4 (기존 services)
  profile.ts        커리어 타임라인 · 케이스스터디 3 · 수상
  stack.ts          기술 스택 그룹
  notes/            동기화 산출물 (아래 6절)
  index.ts          배럴 — 기존 import 경로를 흡수
```

`products.ts`의 사실은 ALM / WIKI / design-system / infra-settings 리포의 코드와 각
`CLAUDE.md`에서 추출한다. **확인하지 못한 사실은 쓰지 않는다.** 스펙 항목이 비면 그 행을
렌더하지 않는다(빈 값 표시 금지).

## 6. 옵시디언 노트 파이프라인

### 6.1 소스 실측

- 경로: `C:\myBrain\내 로컬\msa\MSA_TEMPLATE 정리`
- 대상 22개 md 중 번호 시리즈 20개 (00~19), 총 228KB
- 전 파일 YAML frontmatter 보유 — `tags`, `작성일`, `상태`
- 이미지 참조 0개 → **에셋 파이프라인 불필요**
- 22개 전부 `[[위키링크]]` 사용, 9개가 `> [!note]` 콜아웃 사용 → 변환 필요

### 6.2 `scripts/sync-notes.mjs` (Node, 무의존)

1. 소스 경로는 `OBSIDIAN_VAULT` env로 오버라이드. 미설정 시 위 기본 경로
2. **화이트리스트 = 파일명 `^\d\d ` 정규식**. `auth-server 면접 방어 시트` 등 개인 준비물은
   폴더 안에 있어도 구조적으로 배제된다. 목록을 손으로 관리하지 않는 것이 핵심이다
3. frontmatter 파싱 → `index.json` (번호 · 제목 · 태그 · 작성일 · 상태)
4. 본문 변환
   - `[[대상]]` → 대상이 화이트리스트 내부면 `/tech/notes/<번호>` 링크, 아니면 일반 텍스트로
     평탄화. 끊긴 링크를 0으로 만든다
   - `> [!note]` 콜아웃 → MUI `Alert`로 렌더될 마커로 정규화
5. 산출물 `src/site/content/notes/*.md` + `index.json`을 **git에 커밋**한다.
   볼트가 없는 CI 러너에서도 빌드가 성공해야 한다
6. 볼트 경로가 없으면 경고만 출력하고 **성공 종료** — 기존 산출물을 유지한다
7. 검증 리포트: 화이트리스트 밖 파일 유입 / 깨진 위키링크 / frontmatter 누락

### 6.3 렌더

- `react-markdown` + `remark-gfm`(표·체크박스) + `rehype-slug`(목차 앵커)
- 코드블록은 신택스 하이라이터 없이 모노스페이스 + 가로 스크롤. 번들을 아끼고, 필요해지면
  나중에 shiki를 붙인다
- 노트 인덱스: 태그 필터 + 클라이언트 검색. 20개 규모라 인덱싱 불필요
- 노트 본문: 우측에 목차(데스크톱), 이전/다음 노트 이동

## 7. 리스크

| 리스크 | 대응 |
|--------|------|
| 볼트 경로가 로컬 하드코딩 | env 오버라이드 + 볼트 없으면 스킵하고 성공 종료 |
| 개인 노트 유출 | 파일명 정규식 화이트리스트. 목록 수기 관리 아님 |
| `content.ts` 이동으로 기존 import 파손 | `src/site/content/index.ts` 배럴로 흡수, `tsc -b`가 검출 |
| 신규 의존성 3개 | 승인됨. 하이라이터는 의도적으로 제외 |
| 제품 상세 사실 오류 | 리포 실측만 기재. 미확인 항목은 행 자체를 렌더하지 않음 |
| MUI v9 시스템 props 제거 | `Typography`/`Stack`에 `fontWeight` 등 직접 전달 금지 — 전부 `sx` |

## 8. 검증

이 리포에는 테스트 러너·린터가 없다. 게이트는 다음과 같다.

1. `npm run build` — `tsc -b`(strict / noUnusedLocals / noUnusedParameters)가 타입 게이트
2. `node scripts/sync-notes.mjs` 검증 리포트가 경고 0
3. 수동 확인: 라이트/다크 각각, 375 / 768 / 1024 / 1440 폭
4. 기존 라우트 회귀: `/services/:slug` 4개가 `/tech`의 해당 앵커로, `/app` 로그인 흐름 무손상
5. 링크 점검: GNB · 푸터 · 제품 카드 · 노트 내부 위키링크 전수
