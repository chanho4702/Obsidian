# agent-service — 꺼지지 않는 개발팀 (2026-09-05)

## 0. 목적

**꺼지지 않는 개발팀.** ALM(할 일)·Wiki(기억)·git(결과)을 기록 시스템으로 삼고, 페르소나 에이전트들이 유한한 run의 무한 루프로 일하며, 사람은 과정·산출물·현황을 보고 **게이트에서 판단만** 한다.

사용자 목표 문장: **"git · 태스크 · 담당자 · 위키 · 일정 관리가 한 번에."**
이 중 태스크·담당자·위키·일정 화면은 기존 ALM/Wiki에 이미 있다. 새로 만드는 것은 (1) 에이전트가 거기에 읽고 쓰는 통로(도구 계층 + MCP), (2) git 연결고리, (3) 무인 실행 루프와 감독 UX다.

핵심 통찰 두 가지:
- **팀은 긴 대화가 아니라 run의 루프다.** run 하나는 컨텍스트가 유한하고 끝난다. 팀이 안 꺼지는 이유는 run 사이의 기억이 밖(이슈·위키·git)에 있기 때문이다. Wiki가 에이전트 팀의 장기기억이 된다 — 문서를 안 쓰면 다음 run이 일을 못 하므로 쓰게 된다.
- **에이전트를 만드는 게 아니라 에이전트가 일하는 작업장을 만든다.** 실행기는 검증된 헤드리스 Claude Code(+우리 하네스)를 쓰고, 우리는 두뇌(큐·게이트·예산·기록)와 배관을 만든다.

## 1. 확정 결정 (이 스펙에서 합의)

| # | 결정 | 기각한 대안 |
|---|---|---|
| D1 | 외부 실행(사용자 CLI가 MCP로 접속)과 내부 실행(서비스가 워커를 띄움) **둘 다** 지원. 도구 계층 하나로 두 입구를 받는다 | 한쪽만 지원 |
| D2 | 두뇌는 **Spring AI 기반 agent-service**(신규 리포). `@Tool` 메서드가 MCP 서버 도구이자 내부 ChatClient 도구 | 두 입구 별도 구현 |

| D5 | 하네스 2층: **프로젝트 하네스**(무인 run 기본) + **사용자 하네스**(개인이 시작한 run에만 덮어쓰기). 무인 run에 개인 하네스 적용 안 함(밤에 누구 취향이 돌았는지 추적 불가) | 담당자 하네스로 무인 실행 |
| D6 | 에이전트는 **페르소나 = 플랫폼 멤버**(org-service `kind=AGENT`). 이슈·댓글·문서·커밋이 페르소나 명의로 기록 | 익명 "AI" 표기 |
| D7 | 회의록은 별도 기능이 아니라 **run의 한 종류**(MEETING/REVIEW/RETRO/ESCALATION). 산출물은 Wiki 템플릿 페이지 | 독립 회의 기능 |
| D8 | LLM 자격증명 3층: 플랫폼/프로젝트/사용자 키 모두 가능. 무인 run: 프로젝트>플랫폼. 사용자 run: 사용자>프로젝트>플랫폼 | 단일 소유 |
| D9 | **워커는 기다리지 않는다.** 승인 필요 시 run은 WAITING_APPROVAL로 주차하고 워커 반납. 승인 후 **새 run이 기록(이슈 댓글·회의록)을 읽고 이어받음**. 재개 = 컨텍스트 복원이 아니라 기록에서 재시작 | 워커 대기/세션 보존 |
| D10 | 도그푸딩이 1차 검증: P1 완료 즉시 이 플랫폼 자체 개발을 이 시스템으로 관리 | 별도 테스트 프로젝트 |

## 2. 서비스 구성

```
                 ┌────────────── agent-service (Spring Boot + Spring AI) ─────────────┐
  Claude Code ──MCP──▶ MCP Server ──┐                                                 │
  (외부 CLI)                        ├──▶ 공용 Tool 계층 ──▶ ALM/Wiki/org REST·gRPC     │
  화면/스케줄러 ──▶ Run 실행기 ──────┘        (@Tool)                                   │
                      │  디스패치                                                      │
                      ▼                    진행 이벤트 → Redis Streams → 화면 현황     │
                 agent-worker (컨테이너, run당 1개, 무상태)                            │
                 헤드리스 Claude Code/Codex + 하네스 실체화 + 워크스페이스              │
                 └─── MCP로 agent-service에 진행·기록·게이트 요청 ────────────────────┘
```

| 구성 | 신규/변경 | 역할 |
|---|---|---|
| **agent-service** | 신규 리포 | MCP 서버, 도구 계층, Run 스케줄러·상태머신, 하네스 프로필, 페르소나, 게이트, 예산·자격증명, 런타임 디스패처 |
| **agent-worker** | 신규(이미지) | 헤드리스 실행. run당 1컨테이너, 스케일아웃 단위, 무상태 |
| org-service | 변경 | 멤버 `kind=AGENT` |
| platform-backend(ALM) | 변경 | 이슈 자동화 허용 플래그·현재 run 참조, 활동 스트림 run 이벤트 |
| wiki-backend | 변경 | 회의록 템플릿, 에이전트 저자 |
| alm-front/wiki-front | 변경 | 감독 UI(§8) |
| gateway/infra-settings | 변경 | 라우트, compose, 워커 실행 환경 |

기존 확정 규약 그대로: common-starter JWT, Redis Streams(Kafka 아님), stdout JSON→Alloy→Loki, PostgreSQL, Keycloak, dev 오프셋 +10000.

## 3. 도메인 모델 (agent-service DB)

- **HarnessProfile** — scope(PLATFORM/PROJECT/USER), 롤 정의, 스킬(SKILL.md), 규약 조각, 허용 도구, 선호 런타임, 교차 리뷰 런타임. 런타임 중립 형식.
- **Persona** — org 멤버 참조, 롤(기획/디자이너/프론트/백엔드/운영/리뷰어), 이름·아바타·말투 프롬프트. 기본 6명, 프로젝트별 커스텀. 커밋은 페르소나 git author + `Co-Authored-By`.
- **Run** — type(TASK/MEETING/REVIEW/RETRO/ESCALATION), 이슈·프로젝트 참조, 트리거(SCHEDULER/USER/EXTERNAL), **하네스 스냅샷**(재현용), 런타임, 상태(QUEUED→RUNNING→WAITING_APPROVAL/BLOCKED→DONE/FAILED/CANCELLED), 예산·실사용, 로그 참조.
- **Gate** — run, 종류(PLAN/ISSUE_CREATE/MERGE/ESCALATION), 요청 내용, 결정자, 결정.
- **Credential** — scope 3층, 프로바이더, 앱 레벨 AES 암호화(마스터 키 env).
- **UsageLedger** — scope별 토큰·비용·기간.

## 4. 실행 흐름

**무인 루프:** 스케줄러 tick → 프로젝트 동시성·예산 확인 → "ready + 자동화 허용" 이슈 집기 → Run 생성(프로젝트 하네스) → 워커 디스패치 → 워커: 워크스페이스 준비 → 하네스 실체화 → 런타임 실행(오케스트레이터가 6롤 운용) → MCP로 진행·댓글·문서·게이트 → PR 링크·워크로그 기록 → 리뷰 run(교차 런타임) → 머지 게이트(사람) → 다음 이슈.

**사용자 시작:** 이슈/에픽에서 "에이전트에게 맡기기" → 하네스 덮어쓰기·런타임·자격증명 선택 → 같은 경로.

**외부 CLI:** 개인 토큰으로 MCP 연결 → 같은 도구로 집기·기록. 서버 instructions로 프로토콜(집기→기록→완료 보고)만 유도, 자기 하네스 사용. 우리 기본 하네스 번들 export(`get_harness_bundle`) 제공으로 유도.

**실패:** 재시도 N회 → 초과 시 ESCALATION 회의 run → 사람에게 질문 목록 → BLOCKED. 같은 이슈 무한 반복 금지.

## 5. 도구 계층 (MCP = 내부 = 외부 동일)

- 이슈: `list_ready_issues` `claim_issue` `update_status` `comment` `create_issue` `log_work` `link_pr`
- 위키: `read_page` `search` `write_page`(템플릿 지정) `append_meeting_minutes`
- 프로젝트: `get_context`(규약·최근 결정·회의록 요약 — run 첫 호출) `get_harness_bundle`
- run: `report_progress` `request_gate` `report_result`

모든 호출에 페르소나 ID → 기록 저자. 인증: 워커 = run 단위 단기 토큰, 외부 CLI = Keycloak 개인 토큰 + 대표 페르소나 선택(또는 본인 명의). 권한 검사·감사 로그는 도구 계층 한 곳에서.

**작업 보고서 의무(2026-09-05 사용자 확정):** 에이전트는 계정 있는 팀원처럼 일한다 — 이슈를 집고(claim), 끝낼 때는 반드시 **페르소나 명의의 위키 작업 보고서**(무엇을/왜/어떻게/결과/남은 것)를 쓰고 이슈에 링크 코멘트를 남긴 뒤에만 완료 처리한다. 보고서 없는 완료 금지. MCP 서버 instructions가 이 규약을 강제 문안으로 나른다(P2 워커 하네스에도 동일 적용).

**git 연결:** `link_pr` + 커밋 메시지 이슈 키(`ALM-123`) 규약. 파서(CI 훅 또는 PR 웹훅)가 이슈↔커밋·PR을 자동 연결(P2).

## 6. 회의 run

| 종류 | 참석 페르소나 | 트리거 | 산출물 |
|---|---|---|---|
| 착수/계획 | 기획·디자이너·프론트·백엔드 | 에픽 시작, 사람 요청 | 회의록 + 분해된 이슈들 |
| 리뷰 | 리뷰어·구현 담당 | 작업 완료 | 회의록 + 판정·후속 이슈 |
| 회고 | 전원 | 스프린트 종료·주기 | 회의록 + 개선 이슈 |
| 에스컬레이션 | 관련 롤 | N회 실패 | 회의록 + 사람에게 질문 목록 |

오케스트레이터가 참석 롤을 순서대로 돌려 논의를 모으고 Wiki 템플릿(참석자·안건·논의·**결정**·액션아이템→이슈 링크)을 채움. 결정→이슈 생성은 ISSUE_CREATE 게이트 대상이되 프로젝트 설정으로 자동 허용 가능. 회의록이 다음 run의 "왜 이렇게 결정했지" 답이다.

## 7. 자격증명·비용·안전

- 예산: scope별 월 상한 + run당 상한. 초과 시 해당 scope 큐 정지 + 알림. 사용량은 워커가 런타임 usage 출력 파싱해 보고.
- **킬 스위치**: 프로젝트/플랫폼 단위 즉시 정지.
- 격리: run마다 새 컨테이너, 리포 자격증명은 run-scoped 토큰, egress는 LLM·git·agent-service만, 로그 시크릿 마스킹. 권한 생략 모드는 컨테이너 안에서만.

## 8. 감독 UI (alm-front 중심, P3)

- **팀 탭**: 페르소나 카드 — 상태·현재 이슈·오늘 비용
- **Run 목록/상세**: 타임라인(진행 이벤트), 산출물 링크(PR·문서·회의록), 로그, 승인 버튼
- **게이트 인박스**: 내가 결정할 것만
- 보드: 에이전트 담당 배지, 사람·에이전트 혼합 활동 스트림. 일정은 기존 간트·워크로그가 에이전트 기록으로 채워짐
- 설정: 하네스 편집(프로젝트/개인), 자격증명·예산, **자동화 정책**(무인으로 집을 이슈 조건 — 라벨/컬럼/우선순위)

## 11. AI 부가기능 후보 백로그 (2026-09-05 사용자 요청 — 우선순위 미정)

run 실행(워커)과 별개로, agent-service의 내부 ChatClient(P2에서 배관 확보)로 제공하는 요약·분석류 기능. P1 도그푸딩 시작 시 ALM 이슈로 이관해 우선순위를 정한다.

- **페이지 요약**: 위키 페이지/페이지 트리 요약(긴 문서·회의록 상단 자동 요약 블록)
- **이슈 스레드 요약**: 코멘트·활동 타임라인을 "지금까지 상황" 한 단락으로
- **사용자/팀 활동 분석**: 워크로그·이슈 처리 이력 기반 기여 분석, 스프린트 회고 데이터(리드타임·병목)
- **검색 질의응답**: 위키·이슈 전체에 대한 자연어 질문(기존 검색 인프라 + RAG)
- **초안 생성**: 템플릿 기반 페이지/이슈 설명 초안
- 공통 요건: 같은 자격증명 3층·예산 원장 사용, 결과에 "AI 생성" 표시, 원문 밖 사실 날조 금지 프롬프트 규약

## 12. 솔직한 한계 (재논의 트리거)

- 처음엔 감독된 자율이다. 게이트 완화는 프로젝트별 신뢰 축적 후.
- 온프렘 고객이 외부 LLM API 불가 시 로컬 모델 품질 문제 — 포지셔닝 결정 필요(지금 아님).
- Codex는 서브에이전트 동등물이 없어 프롬프트 수준 페르소나로 동작 — 기록 표면은 동일, 실행 충실도는 낮음.
- 비용은 가동 시간의 함수. 예산 상한 없는 무인 가동 금지.
