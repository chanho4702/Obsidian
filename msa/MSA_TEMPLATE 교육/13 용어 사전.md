## 한글 (가나다순)

**게이트(Gate)**
AI 에이전트가 "병합해도 될까요?"처럼 사람 결재를 요청하는 지점. 종류는 MERGE, ESCALATION, PLAN. 승인하면 이어가는 새 run이 생긴다. → [[12 AI 에이전트 서비스 — 꺼지지 않는 개발팀|12]]

**게이트웨이(API Gateway)**
모든 API 요청이 들어오는 한 개의 입구. 인증 1차 검사, 속도 제한, 서비스로 보내기(라우팅)를 한다. 우리는 Spring Cloud Gateway, 운영 :8000·dev :18000. → [[04 게이트웨이와 서비스 찾기 — Spring Cloud Gateway·Eureka|04]]

**경계 매퍼(mapping.ts)**
서버 응답(DTO)을 화면이 쓰는 타입으로 바꾸는 순수 함수 모음. 서버 모양이 바뀌면 여기만 고친다. → [[07 프론트엔드 — React·Vite·TypeScript와 디자인 시스템|07]]

**공동 초안(collaboration_document)**
공동 편집 중인 Yjs 문서의 정본. `wikidb`에 바이너리로 저장된다. 게시하면 정식 리비전이 된다. → [[08 실시간 공동 편집 — 여럿이 한 문서를 고치는 원리|08]]

**관측(Observability)**
밖에서 시스템 안 상태를 알 수 있게 하는 것. 보통 로그·지표·추적 셋. 우리는 지금 로그만 있다. → [[11 로그와 관측 — Alloy·Loki·Grafana|11]]

**낙관적 락(Optimistic Lock)**
"웬만하면 안 겹치겠지"라고 보고 잠그지 않다가, 저장할 때 버전 번호가 바뀌었으면 거절(409)하는 방식. 위키 일반 저장이 이렇다. → [[05 데이터 — PostgreSQL·Flyway·JPA·낙관적 락|05]]

**대조 워커(Reconcile worker)**
"원하는 값"과 "마지막으로 반영된 값"이 어긋난 행을 주기적으로 찾아 맞추는 일꾼. org-service의 `AuthAccountSyncWorker`는 정지·퇴사한 구성원을 5초 주기로 찾아 auth-server 내부 API(`PUT /internal/users/{id}/status`)로 계정을 닫는다. 상대가 잠깐 죽어도 다음 주기에 다시 맞춘다. → [[03 로그인과 권한 — Keycloak·OIDC·JWT·개인 API 토큰|03]] · [[06 서비스끼리 대화하기 — gRPC·Redis Streams·아웃박스|06]]

**데이터 라우터 / 이탈 가드(useBlocker)**
React Router의 `createBrowserRouter`로 만든 라우터. 이걸 써야 `useBlocker`(앱 안에서 다른 화면으로 나갈 때 "저장 안 한 내용이 있다"고 붙잡는 훅)가 동작한다. 위키가 2026-10-18 이 방식으로 바꿨다. → [[07 프론트엔드 — React·Vite·TypeScript와 디자인 시스템|07]]

**듀얼모드(목업/REST)**
프론트 스토어가 가짜 데이터(목업)와 진짜 서버(REST) 중 하나를 골라 쓰는 구조. 테스트는 항상 목업, 운영 빌드는 항상 REST. → [[07 프론트엔드 — React·Vite·TypeScript와 디자인 시스템|07]]

**디자인 시스템**
여러 앱이 같이 쓰는 화면 부품과 색·간격 규칙. 우리는 `@chanho/tokens`, `@chanho/react`, `@chanho/org-admin`. → [[07 프론트엔드 — React·Vite·TypeScript와 디자인 시스템|07]]

**디자인 토큰**
색, 간격, 글꼴 크기 같은 디자인 값에 이름을 붙인 것. CSS 변수 `--chanho-*`로 만들어진다. → [[07 프론트엔드 — React·Vite·TypeScript와 디자인 시스템|07]]

**라우트(Route)**
"이 경로는 저 서비스로" 하는 게이트웨이 규칙 한 줄. → [[04 게이트웨이와 서비스 찾기 — Spring Cloud Gateway·Eureka|04]]

**라이트 검색(lite)**
검색 전용 서버 없이 위키 서버가 PostgreSQL로 직접 찾는 검색. `SEARCH_MODE` 기본값. 부분 일치, 위키만. → [[09 검색 — 라이트 검색과 OpenSearch|09]]

**러너(Runner)**
① AI 에이전트 작업을 실제로 실행하는 프로그램. 플랫폼 러너(격리 컨테이너)와 내 PC 러너 두 종류. → [[12 AI 에이전트 서비스 — 꺼지지 않는 개발팀|12]]
② GitHub Actions 작업을 실행하는 프로그램. 우리는 이 PC에 self-hosted runner를 둔다. → [[10 배포와 운영 — Docker·nginx·GitHub Actions|10]]

**롤백(Rollback)**
배포한 버전을 이전 버전으로 되돌리는 것. 우리는 `sha-<커밋>` 이미지 태그로 되돌린다. DB 스키마는 되돌아가지 않는다. 백엔드 배포는 헬스 게이트(최대 240초)를 못 넘으면 직전 이미지로 **자동 롤백**한다(`AUTO_ROLLBACK`, 기본 true). 롤백이 성공해도 배포 결과는 실패다. → [[10 배포와 운영 — Docker·nginx·GitHub Actions|10]]

**리셋 세대(reset_epoch)**
다른 경로의 저장 때문에 공동 초안을 새로 시작할 때만 오르는 번호. 게시 세대(generation)와 다르다. → [[08 실시간 공동 편집 — 여럿이 한 문서를 고치는 원리|08]]

**마이크로서비스(MSA)**
큰 프로그램 하나 대신 기능별로 작은 서비스 여러 개로 나눠, 각각 따로 배포하는 구조. → [[02 전체 구조 — 마이크로서비스는 왜 쪼개고 어떻게 연결되나|02]]

**마이그레이션(Flyway)**
DB 테이블 구조를 바꾸는 SQL 파일을 `V1__…`, `V2__…`처럼 번호 순서대로 적용하는 방식. 앞으로만 간다. → [[05 데이터 — PostgreSQL·Flyway·JPA·낙관적 락|05]]

**메모리 상한(mem_limit) / JVM 힙 비율**
컨테이너 하나가 쓸 수 있는 메모리의 천장(compose `mem_limit`) / 그 천장 중 Java 힙으로 쓰는 몫. 2026-10-18부터 상시 컨테이너 전부에 상한이 있고, Java 서비스는 `-XX:MaxRAMPercentage=50`(Keycloak 55%)이다. 넘으면 그 컨테이너만 OOM으로 죽고 재시작된다. → [[10 배포와 운영 — Docker·nginx·GitHub Actions|10]]

**목업(Mock)**
진짜 서버 대신 브라우저 안에서 흉내 내는 가짜 구현. 위키는 localStorage `wiki.v1`에 저장한다. → [[07 프론트엔드 — React·Vite·TypeScript와 디자인 시스템|07]]

**번들 / 코드 분할**
빌드가 여러 파일을 몇 개 묶음(번들)으로 합친 것 / 필요한 화면 조각만 나중에 받게 나누는 것(`React.lazy`, `import()`). → [[07 프론트엔드 — React·Vite·TypeScript와 디자인 시스템|07]]

**서비스 디스커버리**
서비스 주소를 이름으로 찾는 것. 우리는 Eureka를 쓰고, 도커에서는 도커 DNS 이름도 쓴다. → [[04 게이트웨이와 서비스 찾기 — Spring Cloud Gateway·Eureka|04]]

**서킷 브레이커 / fallback**
뒤쪽 서비스가 계속 실패하면 잠시 회로를 열어 바로 실패를 돌려주는 장치 / 그때 대신 내놓는 응답. 게이트웨이의 제품 라우트(wiki·alm·org·agent·migration·search·board)는 연결 실패·응답 타임아웃이면 `/fallback/<서비스>`로 넘어가 `503 {"error": 메시지}`를 준다. → [[04 게이트웨이와 서비스 찾기 — Spring Cloud Gateway·Eureka|04]]

**설치 옵션 스위치**
설치판에서 기능을 켜고 끄는 env 값 하나. 메일은 `MAIL_MODE`, 검색은 `SEARCH_MODE`. → [[09 검색 — 라이트 검색과 OpenSearch|09]] · [[10 배포와 운영 — Docker·nginx·GitHub Actions|10]]

**속도 제한(Rate limit)**
같은 사용자·IP가 너무 자주 요청하면 429로 막는 것. 게이트웨이와 nginx에 있다. → [[04 게이트웨이와 서비스 찾기 — Spring Cloud Gateway·Eureka|04]]

**송신 가드(Egress guard)**
컨테이너가 **밖으로 나가는** 연결을 골라 막는 장치. 플랫폼 러너는 `agent-runner-guard` 컨테이너의 iptables 규칙으로 호스트·사설 대역·링크로컬을 막고 공인 인터넷만 연다. Docker Desktop이 `127.0.0.1`에만 연 포트(Postgres·Redis 등)도 러너에서 닿던 것을 실측하고 넣었다. → [[12 AI 에이전트 서비스 — 꺼지지 않는 개발팀|12]] · [[10 배포와 운영 — Docker·nginx·GitHub Actions|10]]

**스모크 테스트**
배포 직후 "최소한 문은 열리나"만 빠르게 확인하는 시험. 우리는 nginx 경유로 `/`와 `/.well-known/jwks.json`을 본다. → [[10 배포와 운영 — Docker·nginx·GitHub Actions|10]]

**스토어(파사드)**
화면이 데이터를 얻는 유일한 창구. `wikiStore.ts`, `jiraStore.ts`. 목업과 REST를 고른다. → [[07 프론트엔드 — React·Vite·TypeScript와 디자인 시스템|07]]

**실시간 공동 편집**
여러 사람이 한 문서를 동시에 고치고 서로의 커서를 보는 기능. 서버는 있지만 화면 플래그는 꺼져 있다. → [[08 실시간 공동 편집 — 여럿이 한 문서를 고치는 원리|08]]

**아웃박스(Outbox)**
DB 저장과 이벤트 발행을 같은 트랜잭션으로 묶으려고, 이벤트를 먼저 DB 표에 적어 두고 나중에 보내는 방식. → [[06 서비스끼리 대화하기 — gRPC·Redis Streams·아웃박스|06]]

**역색인**
단어 → 그 단어가 들어 있는 문서 목록. 검색 엔진이 빨리 찾는 비결. → [[09 검색 — 라이트 검색과 OpenSearch|09]]

**웹소켓(WebSocket)**
끊지 않고 열어 두는 양방향 연결. 서버가 먼저 말할 수 있다. 공동 편집이 쓴다. → [[08 실시간 공동 편집 — 여럿이 한 문서를 고치는 원리|08]]

**유레카(Eureka)**
서비스들이 "나 여기 있어요"라고 등록하는 전화번호부 서버. 운영 :8761. → [[04 게이트웨이와 서비스 찾기 — Spring Cloud Gateway·Eureka|04]]

**이벤트(Redis Streams)**
"페이지가 바뀌었다" 같은 소식을 스트림에 넣고, 관심 있는 서비스가 읽어 가는 방식. 우리 스트림은 `platform:events:v1`. Kafka가 아니다. → [[06 서비스끼리 대화하기 — gRPC·Redis Streams·아웃박스|06]] · [[09 검색 — 라이트 검색과 OpenSearch|09]]

**입장권(Ticket)**

**컨테이너 / 이미지**

**킬 스위치**

**페르소나(Persona)**

## 영문 (알파벳순)

**actuator (Spring Boot Actuator)**
Spring 앱의 운영용 창구. 우리는 `health`, `info`만 연다. 밖(nginx)에서는 닿지 않는다. → [[11 로그와 관측 — Alloy·Loki·Grafana|11]]

**Alloy (Grafana Alloy)**
도커 소켓으로 모든 컨테이너 로그를 주워 Loki로 보내는 배달부. `infra/observability/config.alloy`. → [[11 로그와 관측 — Alloy·Loki·Grafana|11]]

**ALM**
Application Lifecycle Management. 이슈·스프린트·보드로 일을 관리하는 우리 제품(지라 같은 것). → [[01 우리 제품 한눈에 — WIKI·ALM·AI 에이전트·게시판·제품 사이트|01]]

**AQL**
ALM의 이슈 검색 질의어. 지라 JQL을 본떴다. 서버 AST가 정본, `Asia/Seoul` 기준, 질의 4000자·결과 최대 200. → [[09 검색 — 라이트 검색과 OpenSearch|09]]

**AST**
